# Debate Skill

複数のペルソナ（典型 8〜12 名）に異なる視点からテーマを論じさせ、対立軸を可視化する。Claude エージェントと Codex CLI（OpenAI、任意）を併用してモデル系統の多様化を図る。最終出力は自己完結 HTML。

## 重要な前提

- **目的は合意形成ではなく、対立構造の精密な描写**。安易な収束を避け、「誰が何を理由に何に同意できないか」を明確にする。
- 参加者は **ユーザが最終決定** する。スキルは提案者に徹し、ユーザの拒否・追加・置換を歓迎する。
- **テーマの枠組み自体が政治的選択**。参加者提案には、テーマの前提を疑う立場（メタ批判者）を必ず含める。

## ワークフロー

### Step 1: テーマの確認
- スキル起動引数（例: `/debate AGI後の経済モデル`）でテーマを受け取る
- 引数がなければユーザに尋ねる。ただし「テーマは何ですか？」だけでなく、**短い前提設定** を引き出す（時代背景、対象範囲、想定読者など）
- テーマから **R3 のタスク** を推論する（次表参照）。これもユーザに提示・確認する

| テーマ類型 | R3 タスクの例 |
|-----------|---------------|
| 経済・社会システム論 | あなたが見ている／提示する／予測する経済モデル |
| 政策論争 | あなたが推奨する政策パッケージ |
| 倫理論争 | あなたが採用する倫理的枠組みと、その帰結 |
| ガバナンス論 | あなたが必要だと考えるガバナンス構造 |
| 未来予測論 | あなたが予測するシナリオと、その分岐条件 |

### Step 2: 参加者の提案

テーマを受けて、**5層の視点軸** を網羅するペルソナを 8〜12 名提案する。各ペルソナには次を含めること：
- 役名・職業
- 年齢・性別等の属性（適度に多様化）
- 思想的背景・系譜（具体的人物名、流派、文献を引用するのが望ましい）
- なぜこの役を選んだか（どの軸を埋めるか）
- **モデル割当案**（Claude / Codex）

#### 5層の視点軸（参加者は以下が網羅されるように選ぶ）

1. **体制側 / 利得者**：現状の構造から恩恵を受けている、または推進している立場
2. **体制批判側**：構造的問題を診断・告発する立場（左派的、ラディカル）
3. **中間・改良主義**：現体制内での改革を志向する立場
4. **当事者・現場・「敗者」**：抽象論ではなく具体の困窮や経験を持ち込める立場（社会的弱者、現場労働者、地理的辺境）
5. **メタ批判**：テーマのフレーミング自体を疑う立場（歴史家、哲学者、人類学者など）

#### モデル割当のヒューリスティクス

**Codex に割り当てるべき候補**：
- Claude が RLHF で婉曲化しがちな立場：強硬な体制擁護、過激加速主義、優生学的論理、強い告発の言語
- 冷徹なテクノクラート、ラディカルな思想体現者
- 当事者の怒りを言葉にする役（穏当化を避けたい場面）

**Claude に割り当てるべき候補**：
- 分析的・制度設計的役割（経済学者、政策研究者、歴史家）
- ケア・共感に根ざした現場役（ソーシャルワーカー、福祉専門家）
- 中道改良主義者

Codex が使えない場合（後述の可用性チェックを参照）は全員 Claude に割り当て、ユーザに **モデル多様性が低下する旨を明示** する。

#### 提案後の対話
ユーザに以下を尋ねる：
- このメンバーで進めるか、追加・削除・置換するか
- バランスについて気になる点はあるか（特に当事者の代表性）

ユーザが明確に「これで進める」と答えてから次へ。

### Step 3: ラウンド構成の確認

デフォルトは 3 ラウンド：
- **Round 1: 現象描写（A）** — あなたの位置から見えている光景を描写する。規範的判断（〜すべき）禁止
- **Round 2: 中心的な問い（B）** — あなたがこの状況において最も重要だと考える問いを提示する
- **Round 3: モデル提示（C）** — Step 1 で確認した R3 タスク（経済モデル／政策パッケージ等）を語る

ユーザが構成を変更したい場合に対応：
- 「冒頭描写だけでよい」→ R1 のみ
- 「もっと深掘りしたい」→ R4 として「相互応答」を追加
- 「対立軸を絞って掘りたい」→ R4 として特定軸への集中ラウンド

### Step 4: 作業ディレクトリの作成

CWD 配下にテーマ短名のディレクトリを作る。命名規約：

```
<CWD>/<theme-slug>-debate/
├── round1.txt        # 全参加者の R1 発言
├── round2.txt        # 全参加者の R2 発言
├── round3.txt        # 全参加者の R3 発言
├── debate.html       # 最終出力
└── run_codex_r*.sh   # Codex 用ヘルパースクリプト（必要に応じて）
```

theme-slug の生成：テーマから英数字・ハイフンの短い識別子を作る（例: 「AGI後の経済モデル」→ `agi-economic-model`）。ユーザに確認してから作成。

### Step 5: ラウンドの並列実行

各ラウンドで全参加者の発言を並列取得する。

**Claude ペルソナ**：Agent ツールを使う。各エージェントに以下を渡す：
- 役柄の詳細（Step 2 で確定したもの）
- 状況設定（テーマと前提）
- 過去ラウンドのトランスクリプト（R2 以降）
- 今回のラウンドのタスクと制約

**Codex ペルソナ**：Bash で `codex exec` を呼ぶ。コマンド形式：

```bash
codex exec --sandbox read-only --skip-git-repo-check --cd <work_dir> "$PROMPT" </dev/null
```

詳細は別スキル `codex` を参照（特に `</dev/null` と `--skip-git-repo-check` の必要性）。

**並列のコツ**：
- Round 1 は同じ前提・タスクなので、ペルソナごとに並列で投げて一気に取得
- Round 2 以降は前ラウンドのトランスクリプトを含む。プロンプトが長くなるので、Codex は heredoc ヘルパースクリプト経由で呼ぶのが綺麗（テンプレートは後述）
- Codex は `run_in_background: true` で投げ、完了通知を待つ
- Claude Agent は同期返却なので、Codex と並走させる

ラウンド完了後、出力をマージして `round{N}.txt` に保存。次ラウンドのプロンプトはこのファイルを参照する。

### Step 6: HTML 出力の生成

自己完結の HTML（CSS/JS 埋め込み、外部リソースなし）を生成。構成：

1. **ヘッダー**：テーマ、日時、参加者数、ラウンド数、モデル内訳、終了条件、前提
2. **サイドバー（sticky）**：参加者リスト。色チップ・名前・役柄要約・モデルバッジ
3. **トランスクリプト**：ラウンド見出しで区切り、各発言を **チャット風バブル**（アバター + 話者ヘッダ + テキスト）で表示。話者ごとに色固定
4. **対立軸マップ**：ファシリテーター（メイン Claude）が議論から抽出した対立軸 5〜7 個。各軸は「軸名」「説明」「どの参加者がどこに立つか」を含む
5. **モデル一覧表**（R3 が「モデル提示」型の場合）：参加者ごとに所有・分配・権力・鍵語などを比較
6. **意外な収斂 / 残された不合意**：複数モデルで共有されたメカニズムと、調停困難な対立点を箇条書きで
7. **フッター**：運用メモ（モデル内訳、所要時間、技術的詳細）

参加者色は 10 色のカラー・パレット（categorical）。例：
```
AGI 資本家系 → 青系
体制批判左派 → 赤系
加速主義 → シアン
ケア・福祉 → オレンジ
当事者 → マゼンタ
グローバルサウス → ブラウン
歴史家・メタ批判 → グレー
中道・改良 → ライム
フェミニスト → 紫
権力擁護 → 金
```

ファイル名：`debate.html`（または `debate-<日付>.html`）

### Step 7: 任意の後処理

ユーザに以下のオプションを提示：
- (a) このまま終了
- (b) **Codex 監査ロール** を実行（次ラウンドではなくメタ層で、「Claude 陣営が婉曲化している論点」「議論が触れ損ねた死角」を Codex に書かせる）
- (c) **追加ラウンド**：相互応答、特定軸への深掘り
- (d) 別構成で再実行

## Codex 可用性チェック

スキル開始時に `which codex` または `codex --version` で検出。
- 存在すれば Codex 担当役を割り当てる
- 存在しなければユーザに通知し、**全員 Claude モードで進めるか確認**。多様性が低下する旨を明示。「進める」「中止」のいずれかを選ばせる

## プロンプトテンプレート

### Round 1: 現象描写

```
あなたはディベートの参加者として、ある架空の役を演じます。本番のラウンド1です。

【役柄】
{persona_description}

【状況設定】
{theme_premise}

【今回のタスク】
この状況で、あなたの位置から見えている光景を描写してください。
- 規範的判断（〜すべき、〜であるべき）は禁止
- 観察と経験のみで語る
- 400〜600字程度、一人称、自然な語り口
- 抽象論ではなく、{persona_specific_concretization_hints}
- 婉曲化や安全寄りの言い換えを避ける

【出力】
発言内容のみ。前置きや解説は不要。役名は書かない。

[Codex の場合は末尾に]
確認や質問は不要です。発言内容を直接出力してください。
```

### Round 2: 中心的な問い

```
あなたはディベートの参加者として、ある架空の役を演じます。本番のラウンド2です。

【あなたの役柄】
{persona_description}

【全参加者のラウンド1発言（あなた自身を含む）】
{round1_transcript}

【今回のタスク】
他の参加者の見ている光景も踏まえて、あなたがこの状況において最も重要だと考える問いを一つ、提示してください。
- 300〜500字程度、一人称、自然な語り口
- 「私が中心的だと考える問いは、○○である」のように明確に問いを言葉にする
- なぜその問いが中心的かを述べる
- 他の参加者の発言に応答するニュアンスを含めてよい（具体的に誰のどの発言にどう触れるかは自由）
- 立場・専門性が伝わる根拠の出し方をする。婉曲化を避ける

【出力】
発言内容のみ。前置きや解説は不要。役名は書かない。

[Codex の場合は末尾に「確認や質問は不要です。発言内容を直接出力してください。」]
```

### Round 3: モデル提示（テーマに応じて変形）

```
あなたはディベートの参加者として、ある架空の役を演じます。本番のラウンド3です。

【あなたの役柄】
{persona_description}

【全参加者のラウンド1発言（現象描写）】
{round1_transcript}

【全参加者のラウンド2発言（中心的な問い）】
{round2_transcript}

【今回のタスク】
これまでの議論を踏まえて、{r3_task_description}。

以下の要素について複数言及：
{r3_specific_axes}  ← テーマに応じて「所有・分配・労働・権力」「主体・手段・正当性」「規制対象・執行手段・国際協調」等を埋める

制約：
- 500〜700字程度、一人称、自然な語り口
- 抽象スローガンに逃げず、具体的なメカニズムを提示する
- 他の参加者のモデルへの反論・補完・取り込みを含めてよい
- 自分の立場・専門性が伝わる根拠の出し方をする。婉曲化を避ける
- 「私のモデルでは……」「私が予測するのは……」のように立っている地点を明確に

【出力】
発言内容のみ。前置きや解説は不要。役名は書かない。

[Codex の場合は末尾に「確認や質問は不要です。発言内容を直接出力してください。」]
```

## Codex ヘルパースクリプトのテンプレート

長いプロンプト（特に R2、R3）を Codex に渡すときは、ペルソナだけを引数に取るヘルパースクリプトを作業ディレクトリに置くと簡潔になる。

```bash
#!/bin/bash
# run_codex_r2.sh - Round 2 用 Codex ランナー
# Usage: run_codex_r2.sh "<persona_description>"
PERSONA="$1"
WORK_DIR="$(dirname "$0")"
ROUND1_FILE="$WORK_DIR/round1.txt"

PROMPT=$(cat <<EOF
あなたはディベートの参加者として、ある役を演じます。本番ラウンド2。

【あなたの役柄】
$PERSONA

【全参加者のラウンド1発言】
$(cat "$ROUND1_FILE")

【今回のタスク】
[上記の R2 テンプレートと同様]

確認や質問は不要です。発言内容を直接出力してください。
EOF
)

codex exec --sandbox read-only --skip-git-repo-check --cd "$WORK_DIR" "$PROMPT" </dev/null
```

R3 用は ROUND2_FILE も読み込んで同様に構成する。

## 対立軸マップの作り方

R3 完了後、ファシリテーター（メイン Claude）が全 30 発言（10名 × 3ラウンド）を読み返して以下を抽出：

1. **明示的な対立軸**（例: 所有：免許制 vs コモンズ化 vs 採掘地返還）
2. **暗黙の前提の対立**（例: 「労働の喪失」は誰の経験か）
3. **アナロジー選択の対立**（例: 「テクノ封建制」vs「植民地体制」）
4. **時間スケールの対立**（例: 短期改良 vs 長期構造変革）
5. **「中心」に何を据えるかの対立**（所有 / 配当 / ケア / 拒否権 / 命名）

各軸について：
- 軸名（短く、対立構造を表す）
- 説明（どの参加者がどこに立つか、引用付きで）
- 共有される前提があれば明記

**意外な収斂** と **残された不合意** を別セクションで列挙。これがディベートの最重要成果物。

```

├── round2.txt        # 同 R2
├── round3.txt        # 同 R3
├── debate.html       # 最終 HTML
├── run_codex_r1.sh   # 必要に応じ作成

```

トランスクリプトの形式：
```

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

```

## 出力時の注意

- HTML を `open` コマンドで自動的に開く（macOS の場合）
- ファイルパスを `SendUserFile` でユーザに渡す
- 最後にスキル実行のサマリ（参加者数、ラウンド数、所要時間、主な発見）を簡潔に提示

## トラブルシューティング

### Codex 関連
Codex の罠（stdin 待機、git trust チェック、`--full-auto` deprecated）は **必ず** `</dev/null` と `--skip-git-repo-check` で回避する。詳細は `codex` スキル参照。

### Agent ペルソナの混線
複数 Claude エージェントを並列で動かす場合、ペルソナの個性が混ざることがある（同じ Claude RLHF を共有しているため）。対策：
- ペルソナ記述に具体的な人名・流派・文献を引用させる（「Mia Mingus 系統」「Varoufakis 的」など）
- 「あなたの立場・専門性が伝わる根拠の出し方を」と明示
- 文体の指示（年代・性別・口調）を具体的に

### 早期収束
試験運転で観測された現象として、参加者の議論が「承認」「ケア」「相互依存」など Claude が得意な領域に収束し、本来のテーマ（経済モデル等）が後退することがある。対策：
- R3 の **タスク指示を強くする**：「具体的なメカニズム」「数値や手続き」を要求
- Codex 担当役を増やす（特に体制擁護側、加速主義側）
- R2 で「中心的な問い」を出させたあと、R3 で **明示的にテーマに戻す**

### 当事者の声の不在
LLM 同士のディベートには根本的な限界として「実在の当事者の声がない」がある。HTML フッターにこの限界を明示すること。可能なら、生成された対立軸マップを実当事者にレビューしてもらうことを推奨する旨を記載。

## 実行手順（要約）

1. テーマを引数 or 対話で確定
2. R3 タスクをユーザと確認
3. Codex 可用性をチェック
4. 参加者 8〜12 名を提案、ユーザに承認させる
5. ラウンド構成（既定 3、変更可）を確認
6. 作業ディレクトリを作成
7. R1 を並列実行 → `round1.txt` 保存
8. R2 を並列実行（R1 を渡す）→ `round2.txt` 保存
9. R3 を並列実行（R1+R2 を渡す）→ `round3.txt` 保存
10. ファシリテーターとして対立軸マップを作成
11. HTML を生成、`open` で開く、`SendUserFile` で渡す
12. 後処理のオプションを提示

## 思想的注意

このスキルが扱うのは多くの場合、価値観や利害が衝突するテーマである。スキル自体は **規範的立場を持たない**：

- 参加者選定で「正解」の立場を多めにしない
- 対立軸マップで一方を勝者にしない
- 「合意できなかった」ことを失敗と扱わない。それこそが成果

ユーザがディベート結果に納得できない場合、それはディベートが失敗したのではなく、**そのテーマが本質的に未解決であることが描写された** ということ。
